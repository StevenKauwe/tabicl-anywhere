BrowserTabICL · measured on an i7-11700K and RTX 3090 · 13 Oct 2026

Half a gigabyte of memory, read through a one-megabyte window

An independent Rust implementation of the TabICL v2 tabular model, for classification and regression. It gives the same answers as the published PyTorch code, predicts while holding about 12 MB because everything it learned about the training table stays on disk and is played past like tape, and also runs in a browser as 1.4 MB of WebAssembly.

One prediction against 10,000 training rows of 100 features. Each of the model's 12 in-context layers needs every training row's keys and values, 41 MB per layer. The whole 491 MB goes past in chunks of 256 rows; only the running totals are kept.

The reference keeps the cache in RAM, so it never pays to read it. Its 6.3 GB is the peak of the whole process, fit included; its memory during prediction alone was not measured. "From disk" rows hold about 12 MB; "warm" rows keep the cache in RAM (the optional in-memory tier), which costs its size in memory. On batches the reference is still about twice as fast: its matrix library is better than these kernels.

Reading already runs at memory speed (about 16 GB/s from the page cache), so the lever is fewer bytes. That is what the smaller cache formats are for.

How it works

Three stages, one file

ColumnsEach cell is described relative to its column. Per column, 128 summary points are stored at fit time (393 KB a column); a new cell consults only those.
RowsA row's 100 cells talk to each other and condense into one 512-number description. Needs nothing from the training table.
In contextThe new row compares itself with every training row, 12 times over. This is the tape: 98% of the file.
  • Running average instead of a table. Attention is a weighted average over all training rows. Keeping the largest score seen, the total weight and the weighted sum lets rows arrive in pieces and be forgotten.
  • Laid out in reading order. The file is written in the order prediction consumes it, and read through a "bytes X to Y" interface: a local file, bytes in memory, or object storage such as S3.
  • Batches share a pass. 64 rows cost one trip through the cache, not 64: 2.9 ms a row.
  • Sealing. The file is cut into 64 KB blocks, each encrypted and tamper-checked on its own, so any range can still be fetched and opened alone.
  • Warm tier. Optionally, pieces that stream past are kept in memory and used in place next time. Every entry belongs to one tenant and model, each tenant has its own byte budget, and nothing is freed while a prediction still uses it.
  • Graphics card. One portable shader (Vulkan, Metal, DirectX; the same language browsers use) does the step of fitting that grows with the square of the table.
  • Safe Rust only. #![forbid(unsafe_code)]; one set of kernels compiles to AVX2, NEON or plain code and picks at run time.
